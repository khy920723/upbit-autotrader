# 요구사항 정의서

상태: 확정 · 2026-11-03 · 2026-11-07 FR-07을 하지 않음으로 바꿈(D-097) · 요구사항이 바뀌면 [결정 로그](../10-management/decision-log.md)에 먼저 기록한다.

## 1. 사용자 원 요구사항

| # | 사용자 요구사항 | 반영 |
|---|---|---|
| U1 | Windows 시작 시 시작 앱으로 등록해 자동으로 매매 시작 | FR-01, FR-02 |
| U2 | API 키 같은 중요 정보는 최초 실행 때 입력받아 저장 | FR-03 |
| U3 | 앱 실행 시 전체 코인 목록 수신 | FR-04 (주기 갱신 추가) |
| U4 | 최대 3개 코인 선택, 긍정·부정 시그널로 매매 | FR-05, FR-08~FR-11, FR-15(부정 시그널은 기본적으로 신규 매수 차단, 매도는 옵션이며 기본 꺼짐) |
| U5 | 시그널은 무료 LLM으로 평가 | FR-08 (Gemini API 무료 등급) |
| U6 | 손해는 최소, 이익은 최대 | FR-10, FR-13 (손실 상한 강제). 수익 보장은 불가 |

| NFR-09 | 유지보수 | 의존성 버전 고정(uv.lock), 핵심 로직 테스트, CI 통과 후 병합 |
| NFR-10 | 법·약관 | 자기체결 방지, 최소 주문 간격, 일일 주문 수 상한, 각 서비스 약관 준수 |
| NFR-11 | 사용성 | 한국어 화면. 오류 문구에 원인과 해결 방법 포함 |

## 4. 실행 모드

| 모드 | 설명 |
|---|---|
| backtest | 과거 캔들로 규칙·위험 관리만 검증하는 개발용 도구. LLM 시그널은 쓰지 않음 |
| paper (기본) | 실시간 시세, 가상 체결. 수수료·슬리피지·최소 주문 금액 반영 |
| signal-only | 시그널과 "냈을 주문"만 기록 |
| live-validate | 주문을 `/v1/orders/test`로 보내 검증하고, 통과하면 가상 체결로 포지션 유지. 실제 체결 없음. 인정일 28일 + 체크리스트 A 이후 가능 |
| live | 실제 주문. live-validate 3일 이상 + 체크리스트 B + 확인 문구 입력 후 켬 |

## 5. 하지 않는 것

다른 사람의 자금 운용, 앱 판매·시그널 제공, 고빈도 매매, 입금·출금, 해외 마켓, 모바일·서버 배포, 뉴스 수집(약관, D-097).
