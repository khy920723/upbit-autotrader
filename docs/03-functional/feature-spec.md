# 기능 명세서

상태: 초안 · 관련: [요구사항 정의서](../01-planning/requirements.md), [매매 로직 명세](trading-logic.md), [상태 전이 정의서](state-machines.md)

요구사항 ID(FR-xx)를 그대로 기능 ID로 쓴다. 화면 동작은 [화면 정의서](../02-ux/screen-spec.md), 매매 판단은 [매매 로직 명세](trading-logic.md), 한도는 [위험 관리 정책서](risk-policy.md)에 있다.

## 1. 기능 상세

### FR-01 자동 실행

- 마법사나 설정에서 "Windows 시작 시 실행"을 켜면 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 등록한다(관리자 권한 불필요). 끄면 지운다.
- 자동 로그인과 함께 쓰면 재부팅 후 사람 없이 실행된다. 자동 로그인 설정은 앱이 하지 않고 [설치 가이드](../09-operations/install-guide.md)로 안내한다.
- 시작 앱은 로그인 직후 늦게 실행될 수 있으므로, 실행 후 네트워크가 준비될 때까지 기다린다.
- 앱은 시작할 때마다 Run 항목의 경로가 현재 exe 경로와 같은지 확인하고, 다르면(자동 실행이 켜져 있을 때) 갱신한다.

### FR-02 시작 점검과 자동 재개

| 순서 | 점검 | 실패 시 |
|---|---|---|
| 1 | 네트워크 연결(최대 5분 대기) | SUSPENDED, 연결되면 다시 점검 |
| 2 | 키 저장소 읽기 | HALTED(MSG-E009) |
| 3 | PC 시계와 거래소 시각 차이 ≤ 5초 | DEGRADED(MSG-E010) |
| 4 | 업비트 키: 잔고 조회로 유효성·허용 IP 확인, `GET /v1/api_keys`로 만료일 확인 | live 계열: HALTED(MSG-E001~E003) / paper: 경고 |
| 5 | 종목 목록·경고 갱신 | 직전 값으로 계속 + 경고 |
| 6 | 잔고·미체결 주문을 로컬 기록과 대조(실제 자산이 걸린 포지션이 있을 때: live와 exit_only 실보유분. live-validate·paper 포지션은 가상이라 대조하지 않음) | 차이를 거래소 기준으로 맞추고 기록 |
| 7 | Gemini 연결(생성 호출 없이 모델 정보 조회) | 경고, 시그널은 중립 처리 |

- 모두 통과하면 직전 모드와 상태로 재개한다(MSG-I001, NTF-01). 복원 규칙은 [상태 전이 정의서](state-machines.md) 2장.
- 거래소 상태는 언제나 로컬 기록보다 우선한다.
- 대조 규칙: [매매 로직 명세](trading-logic.md) 11장(D-053). 선택 코인의 보유 수량은 거래소 값(`balance + locked`)으로 덮어쓰고, 평균 단가는 거래소의 `avg_buy_price`를 쓴다(수동 매매 포함). 앱 주문은 identifier 접두어 `uat-`로 구분한다. 선택하지 않은 코인의 보유분은 관리하지 않고 경고 이벤트로만 남긴다. 차이를 고쳤으면 MSG-W010으로 알린다(NTF-20).

### FR-04 종목 목록과 경고

- `/v1/market/all?is_details=true`로 KRW 마켓만 저장한다.
- `market_event.warning`(유의)과 `market_event.caution`의 각 항목(주의)을 저장한다. 시세 웹소켓의 `market_state`, `delisting_date`와 공지 웹소켓 `announcement`(category trade)도 반영한다.
- 갱신 시점: 실행할 때, 3시간마다, 웹소켓 재연결이나 잠자기 복귀 직후.

### FR-06 시세와 지표

- 선택 코인의 ticker를 공개 웹소켓으로 받는다. 끊기면 지수 백오프로 재연결하고 REST로 빈 구간을 채운다.
- 지표 계산용 캔들은 REST로 받아 로컬에 캐시한다(요청당 최대 200개, 거래 없는 구간은 캔들이 없음).
- 지표 종류와 캔들 단위는 규칙 조건(ADR-0007, 대기)과 함께 정한다.

### FR-07 뉴스 수집

- 시그널 평가 직전에 코인별로 수집한다. 상세는 [뉴스 수집 명세](../05-integration/news-collection.md).

### FR-08 시그널 평가

- 4시간마다 코인별로 순서대로 평가한다. 상세는 [LLM 시그널 명세](../05-integration/llm-signal.md).
- 실패(타임아웃, 429, 형식 오류, 거절)는 모두 중립으로 처리하고 기록한다. 3번 연속 실패하면 알린다(NTF-11). 403(프로젝트 확인 필요)은 다시 호출해도 풀리지 않으므로 LLM 호출을 멈추고 알린다(MSG-E018, NTF-22).
- 429는 분당 한도와 일일 한도를 구분해 처리한다([LLM 시그널 명세](../05-integration/llm-signal.md) 6장).

### FR-11 주문

- 주문 생성 규칙·흐름·결과 불명 확인·업비트 state 대응은 [매매 로직 명세](trading-logic.md) 7~10장, 재조정은 11장.
- 같은 코인에 결과를 모르는 주문이 있으면 새 주문을 보내지 않는다.

### FR-13 긴급 정지 / FR-14 재진입 / FR-15 LLM 부정 매도

- [위험 관리 정책서](risk-policy.md) 3~5장.

### FR-17 기록과 내보내기

- 주문, 주문 상태 변화, 체결, 시그널(입출력 원문), 결정, 이벤트, 알림을 SQLite에 기록한다. 구조는 [데이터 모델](../04-data/data-model.md).
- CSV 내보내기는 기간을 골라 거래 기록과 일별 손익을 저장한다.

### FR-20 키 만료 알림

- 업비트에 `GET /v1/api_keys`(API Key 목록 조회)가 있다(2026-11-05 확인). 인증만 필요하고 별도 권한은 필요 없다. JOB-08이 하루 1회 조회해 자기 `access_key`의 `expire_at`을 만료일로 쓴다(D-050).
- 조회가 실패하거나 목록에 자기 키가 없으면 마법사에서 받은 발급일 + 1년을 쓴다. 30일, 7일, 1일 전에 알린다.

### FR-21 허용 IP 오류

- 주문할 때나 10분마다 하는 정기 점검(JOB-14)에서 업비트 오류 `no_authorization_ip`를 받으면 HALTED로 바꾸고, 현재 공인 IP를 확인해 MSG-E001과 긴급 알림을 보낸다. 정기 점검 덕분에 손절이 필요해지기 전에 IP 변경을 알 수 있다.
- 업비트 오류 응답에는 IP가 없다. 현재 공인 IP는 필요할 때만 외부 조회 서비스로 확인한다([시스템 구성도](../06-architecture/system-architecture.md) 8장, 제안 D-051 대기).

### FR-22 절전 방지와 복귀

- 매매 중에는 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`로 유휴 절전을 막는다. 사용자가 직접 절전을 고르는 것은 막을 수 없다.
- 잠자기 복귀(`PBT_APMRESUMEAUTOMATIC`)를 감지하면 웹소켓 재연결, 잔고·미체결 대조, 종목 갱신을 한 뒤 재개한다. 꺼져 있던 동안의 시그널은 실행하지 않는다.

### FR-23 트레이와 중복 실행 방지

- 창 닫기(X)는 트레이로 숨긴다. 종료는 트레이 메뉴에서만 하고 MSG-C005로 확인한다.
- 두 번째 실행은 기존 창을 띄우고 바로 끝난다. 방법은 QLockFile(데이터 폴더의 `app.lock`) + QLocalServer다([시스템 구성도](../06-architecture/system-architecture.md) 8장, 제안, D-052 대기).

### FR-24 백테스트

- 과거 캔들로 규칙 조건과 위험 관리만 검증한다. LLM 시그널은 쓰지 않는다(look-ahead bias).
- 수수료·슬리피지·최소 주문 금액을 반영한다.

### FR-25 자가 점검

- `autotrader.exe --self-test`: 창 없이 import, Qt(offscreen), keyring 백엔드, SQLite, TLS 인증서, 설정 경로를 점검하고 `self-test-report.txt`를 쓴 뒤 0(성공) 또는 1(실패)로 끝난다. 네트워크와 키는 쓰지 않는다.

|---|---|---|---|---|

| JOB-03 | 시그널 평가 | 4시간(설정) | 코인별: 뉴스 → 지표 요약 → LLM → 규칙 → 위험 → 주문 | 중립 처리 |

| JOB-05 | 주문 재조정 | 30초 + myOrder 이벤트 | 미체결·결과 불명 주문 조회 | 다시 조회, 새 주문 보류 |

| JOB-07 | 일일 요약 | 매일 09:00 KST(설정) | 전날 손익·거래·시그널 요약 알림 | 다음 요약에 포함 |
| JOB-08 | 키 만료 점검 | 하루 1회 | `GET /v1/api_keys`로 만료일 갱신, 30·7·1일 전 알림 | 조회 실패 시 발급일 + 1년 |
| JOB-09 | 시계 오차 점검 | 1시간 | 거래소 서버 시각과 비교 | 5초 초과 시 DEGRADED |

| JOB-13 | 인정일 갱신 | 매일 09:00 KST | 전날이 페이퍼 인정일인지, live-validate 인정 일인지(D-049) 계산 | - |
| JOB-14 | 키·IP 상태 점검 | 10분(live 계열. paper에 exit_only 실보유분이 있으면 paper에서도, D-068 대기) | GET /v1/accounts 1회로 허용 IP와 키 유효성 확인 | no_authorization_ip·키 오류면 HALTED + NTF-03. paper의 exit_only는 그 주문만 멈추고 NTF-23 |

- 하루의 기준은 업비트 일봉 경계인 09:00 KST다.
- 주기는 PC 시계가 아니라 monotonic 시간으로 재고, 날짜 경계는 거래소 서버 시각으로 판단한다.
- 4시간 평가 시각 정렬은 [매매 로직 명세](trading-logic.md) 5장(제안: 4시간봉 마감 + 2분, D-057 대기, ADR-0007과 함께 결정).
