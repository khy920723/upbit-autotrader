# 위험 관리 정책서

상태: 확정(수치는 초안) · 관련: [매매 로직 명세](trading-logic.md), [상태 전이 정의서](state-machines.md), [설정 항목 정의서](settings.md)

## 1. 원칙

1. 위험 관리는 주문 직전의 마지막 관문이다. 어떤 시그널, 규칙, 설정 조합도 이 검사를 건너뛸 수 없다. 우회 옵션이나 디버그 플래그를 만들지 않는다.
2. 손실을 줄이는 방향(손절, 청산)은 거래소와 통신할 수 있는 한 막지 않는다. 예외는 사용자가 "정지"를 누른 경우다.
3. 불확실하면 매수하지 않는다. 데이터가 의심스럽거나(시세 끊김, 시계 오차), 주문 결과를 모르면 신규 매수를 멈춘다.
4. 모든 거부와 차단은 이유 코드로 기록한다.

## 2. 한도

기본값은 페이퍼 시작용 예시다. 투자 판단이 아니며, 사용자가 마법사와 설정에서 직접 정한다. 실전 전환 전에 반드시 다시 확인한다.

| 항목 | 정의 | 기본값(초안) | 위반 시 |
|---|---|---|---|
| 코인별 예산 | 한 코인의 보유 평가금액 + 미체결 매수 금액 상한 | 10,000원 | 주문 금액을 줄이거나 거부 |
| 예산 하한 | 손절 시점에도 팔 수 있는 금액: 최소 주문 금액 ÷ (1 − 손절%/100) × 1.1 이상. 분할 매수면 회차당 금액 기준 | 계산값(기본 설정에서 약 5,800원) | 마법사·설정 저장 거부 |
| 전체 노출 상한 | 모든 코인의 노출 합계 | 코인별 예산의 합(30,000원) | 거부 |
| 최소 주문 금액 | 업비트 `min_total`(현재 5,000원) 미만 금지 | API 값 | 거부, 사이징 오류로 기록 |
| 손절 | 평균 단가 대비 평가손실률 | 5% | 시장가 전량 매도 |
| 익절(선택) | 평균 단가 대비 평가수익률 | 꺼짐 | 시장가 전량 매도 |
| 일일 손실 한도 | 09:00 KST부터 실현 손실 합계 | 3,000원(예산 합의 10%) | 그날 신규 매수 중지(BUY_BLOCKED) |
| 최소 주문 간격 | 같은 코인의 연속 주문 사이 | 60초 | 다음 기회까지 대기 |
| 일일 주문 수 상한 | 하루 전체 주문 수 | 20건 | 신규 매수 중지. 손절 매도는 허용 |
| 확신도 임계값 | 시그널을 쓰는 최소 확신도(매수·부정 매도 공통) | 0.7 | 매수 안 함 |
| 데이터 의심 | 시세 웹소켓 끊김 120초 초과, 시계 오차 5초 초과 | - | DEGRADED: 신규 매수 중지, 손절은 REST 현재가로 계속 |
| 통신 불가 | 네트워크 끊김, 418 차단 | - | SUSPENDED: 주문 불가, 원인 해소 시 자동 재점검 |
| 결과 불명 주문 | 같은 코인에 확인 안 된 주문 존재 | - | 그 코인의 새 주문 보류 |
| 경고 종목 | 유의, 주의 플래그, 거래지원 종료 예정 | 항상 | 신규 매수 금지 |
| 거래소 오류 | 허용 IP 오류, 키 만료·무효(live 계열) | - | HALTED |

- 업비트 요청은 한도의 절반 이하로만 쓴다(NFR-06).
- 수수료, 최소·최대 주문 금액은 `/v1/orders/chance`에서 읽는다. 하드코딩하지 않는다.
- 기본 설정(예산 10,000원)에서는 최소 주문 금액 때문에 분할 매수를 할 수 없다.

## 3. 일시정지, 긴급 정지, 다시 시작

| 버튼 | 동작 | 이후 상태 |
|---|---|---|
| 일시정지 | 신규 매수 중지. 손절·익절·청산 매도는 계속 | PAUSED |
| 정지 | 모든 신규 주문 중지 + 미체결 주문 취소. 손절도 멈추고, 손절선에 닿으면 알림만 보냄(MSG-C001) | STOPPED |
| 정지 후 전량 매도 | 정지 + 보유 코인 시장가 매도(확인 문구 입력, MSG-C002) | LIQUIDATING → STOPPED |
| 시작 | STOPPED에서만 표시. 시작 점검을 통과하면 매매 재개(MSG-C009) | CHECKING → RUNNING |

- 긴급 정지 두 버튼은 대시보드와 트레이 메뉴에 모두 있다.
- 전량 매도에 실패한 코인(최소 주문 금액 미만, 거래 정지 등)은 결과 알림(MSG-W009)에 따로 표시한다.

## 4. 손절 후 재진입

손절했다고 그 코인의 매매를 막을 필요는 없다는 것이 기본 방침이다. 기능으로는 아래 옵션을 둔다.

| 옵션 | 동작 |
|---|---|
| 제한 없음(기본) | 손절 직후에도 조건이 맞으면 매수 가능 |
| N시간 뒤 허용 | 손절 체결 후 N시간(기본 24) 동안 매수 금지 |
| 그날은 금지 | 다음 09:00 KST까지 매수 금지 |
| 직접 풀 때까지 금지 | 대시보드 코인 카드의 [재진입 허용] 버튼(MSG-C010)을 눌러야 매수 가능 |

## 5. LLM 부정 시그널

- "부정"은 확신도가 임계값(`signal.confidence_threshold`, 매수와 같은 값) 이상인 negative를 말한다.
- 기본: 신규 매수만 막는다(보유분은 유지).
- 설정에서 켜면: 보유분을 시장가로 매도한다. RUNNING, PAUSED, BUY_BLOCKED 상태에서 청산으로 실행한다.

## 6. 실전 전환 게이트

### 인정일

- paper 모드에서 RUNNING, PAUSED, BUY_BLOCKED 상태였던 시간의 합이 하루(09:00 KST 기준) 12시간 이상이면 인정일 1일로 센다.
- signal-only 모드는 세지 않는다. 연속이 아니라 누적으로 센다. live에서 paper로 돌아와도 누적은 유지한다(초안).
- 인정일은 DB(daily_stats)로만 계산한다. 설정 파일로 바꿀 수 없다.

### 두 번 확인

| 전환 | 조건 | 체크리스트 |
|---|---|---|
| paper → live-validate | 인정일 28일 이상 | A: 키 검증 통과, 키가 봇 전용 서브 포켓에서 발급한 키, 권한 3개만(자산조회·주문조회·주문하기), 허용 IP가 현재 IP와 일치 |
| live-validate → live | live-validate 3일 이상(앱이 강제), 매수 검증 오류 0건 | B: 위험 한도 다시 확인, 알림 동작 확인, 긴급 정지 버튼 위치 숙지, 서브 포켓에 감당할 수 있는 소액만 / 확인 문구 "실전 전환" 입력(MSG-C004) |

- live-validate는 주문을 업비트 주문 검증 API로 보내고, 통과하면 paper처럼 가상 체결로 포지션을 유지한다. 실제 보유가 없어서 생기는 매도 검증의 잔고 부족 오류는 예상된 결과로 따로 집계한다.
- 체크리스트 A 확인 방법(제안, D-048 대기): 서브포켓 키로는 자기 포켓·권한 목록·허용 IP 목록을 API로 조회할 수 없다(포켓관리 권한이 있는 메인포켓 키만 가능, [업비트 API 연동 명세](../05-integration/upbit-api.md) 1장). 그래서 앱은 키 검증(인증 호출 성공 = 현재 IP 허용)과 권한 3개의 동작(잔고 조회·주문 조회·주문 검증 성공)을 자동으로 확인하고, "봇 전용 서브포켓에서 발급한 키"와 "권한이 3개뿐"은 사용자가 업비트 화면에서 보고 확인 표시한다.
- live-validate 3일은 인정일과 같은 규칙(그날 live-validate 모드의 RUNNING·PAUSED·BUY_BLOCKED 시간 합이 12시간 이상)으로 센다(제안, D-049 대기).

### live → paper

- 언제든 바꿀 수 있다. 실제 보유 코인이 있으면 MSG-C008로 다음 중 하나를 고른다.
  - 시장가 매도 후 전환
  - 실보유분은 손절·청산만 계속 관리하고 전환(신규 매수 없음)
  - 취소
- 어떤 경우에도 실제 보유분을 관리 없이 남기지 않는다.

## 7. 시세조종 오인 방지

가상자산이용자보호법은 시세조종을 처벌하고, 금융위원회는 2025-11-05 API로 초당 여러 번 소액 매수·매도를 반복한 사례를 수사 의뢰했다. 앱은 다음을 지킨다.

- 자기 주문끼리 체결되지 않게 한다(동시 매수·매도 금지, `smp_type` 명시).
- 최소 주문 간격과 일일 주문 수 상한을 지킨다.
- 주문을 반복해서 걸었다 취소하지 않는다. 취소 후 재주문은 위험 검사부터 다시 한다.
- 모든 주문을 이유와 함께 기록한다.

## 8. 설정 변경

- 한도를 느슨하게 바꾸면 확인을 받는다(MSG-C006). 엄격하게 바꾸는 것은 바로 적용한다.
- live 모드에서 한도를 바꾸면 이벤트로 기록하고 알린다.
