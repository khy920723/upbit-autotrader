# 분할 매수·매도 설계

상태: 확정(사용자 결정: 2026-11-05 D-082, D-083, D-084, D-085, D-043, 2026-11-06 D-086) · 구현은 5단계 · 관련: [ADR-0008 매수·매도 분할](../06-architecture/adr/0008-buy-method.md), [위험 관리 정책서](risk-policy.md), [매매 로직 명세](trading-logic.md), [설정 항목 정의서](settings.md), [상태 전이 정의서](state-machines.md), [데이터 모델](../04-data/data-model.md)

사용자 요청(2026-11-05, D-043 질문에 직접 적은 답, 지휘 세션 전달): 분할 매수·매도를 위한 알고리즘을 다시 설계하고, 몇 단계로 몇 퍼센트씩 나눌지는 사용자에게 입력받는다. 같은 날 사용자가 9장의 항목을 골랐고, 2단계 하락률 기본값(D-086)은 2026-11-06에 골랐다.

## 1. 요약

| 결정 | 정한 내용 |
|---|---|
| D-082 분할 구조 | 매수 단계별 비율과 익절 단계(발동 수익률·매도 비율)를 사용자가 입력한다. 기본은 매수 1단계 100%(한 번에)와 익절 꺼짐이라, 바꾸지 않으면 나누지 않는다 |
| D-083 단계 수 상한 | 매수 최대 2단계, 익절 최대 2단계(사용자가 직접 적은 값). 코인당 한 사이클 최대 주문 4건, 코인 3개면 12건 |
| D-084 2단계 조건 | 시그널 평가 때 매수 조건(LLM 긍정 + 규칙 + 위험 한도, D-006. 2026-11-10 D-114로 예상 결과 보고서 판정 + 위험 한도로 바뀜, [분석 보고서 세션 제안서](analysis-report-session.md) 10.3절)을 다시 모두 만족하고, 현재가가 평균 단가보다 하락률 이상 낮을 때만 2단계를 산다. 하락률은 사용자가 입력한다(0 < 하락률 < 손절%) |
| D-085 분할 매도 범위 | 익절만 나눠 판다. 손절과 그 밖의 청산은 전량이다. 나눠 판 뒤 남는 부분이 손절 때 팔 수 없을 만큼 작으면 그 단계에서 전량 판다. 첫 익절 뒤에는 더 사지 않는다 |
| D-043 주문 유형 | 매수 단계는 최유리 FOK, 매도(익절 단계 포함)는 시장가. 페이퍼는 호가로 체결을 계산한다 |
| D-086 하락률 기본값 | 2%(선택지 B). 사용자가 직접 고른 값이며 앱이나 지휘 세션이 권한 값이 아니다. 손절 %가 2% 이하이면 기본값을 비우고 직접 입력한다(3.2) |

- **안전 장치:** 단계 금액 ≥ 예산 하한, 나눠 판 뒤 남는 부분도 손절 때 팔 수 있어야 함, 하루 주문 수 검사, 단계 수 상한, 익절을 시작하면 더 사지 않음, 단계 계획은 포지션을 열 때 고정.
- **"최적"의 기준:** 수익이 아니다. 투자 자문이 아니므로 수익률을 적거나 특정 값을 권하지 않는다. 위험 관리 규칙을 항상 지키고, 팔 수 없는 잔량과 고빈도 소액 반복 주문을 만들지 않으며, 사용자가 동작을 미리 알 수 있게 설계했다.
- LLM 시그널의 성과는 과거 데이터로 백테스트하지 않는다. 단계 금액, 잔량, 주문 수 규칙은 규칙·위험 관리 부분이라 시뮬레이션으로 확인할 수 있다(FR-24).
- 이전 안(ADR-0008 제안, D-039: 기본 한 번에, 균등 2~3회, 다음 회차는 새 긍정 시그널, 매도 전량)은 D-082로 대체했다.

## 2. 용어와 기준값

| 용어 | 뜻 |
|---|---|
| 단계 | 포지션 하나를 나눠 사거나 파는 주문 하나. 이전 문서의 "회차"와 같다 |
| 예산 하한 F | 올림(매도 최소 주문 금액 ÷ (1 − 손절%/100) × 1.1). 손절 5%, 최소 주문 금액 5,000원이면 5,790원([위험 관리 정책서](risk-policy.md) 2장) |
| 단계 금액 | 내림(코인별 예산 × 단계 비율 ÷ 100). 그 단계에서 살 수 있는 최대 금액 |
| 하락률 d | 2단계를 사려면 현재가가 평균 단가보다 이만큼(%) 이상 낮아야 한다 |
| 평균 단가 | 수수료를 뺀 매수 체결가의 수량 가중 평균([매매 로직 명세](trading-logic.md) 12장) |
| 손절선 | 평균 단가 × (1 − 손절%/100) |
| 기준 수량 | 첫 익절 단계를 팔기 직전의 보유 수량. 익절 비율은 이 수량에 곱한다 |
| 사이클 | 포지션이 FLAT에서 열려 다시 FLAT으로 돌아갈 때까지 |

- 최소 주문 금액과 수수료는 그 순간의 `/v1/orders/chance` 값을 쓴다(매수는 bid, 매도는 ask, D-067). 키 없는 paper는 공식 문서 값을 추정값으로 쓴다(D-059 대기).
- 이 문서의 숫자는 최소 주문 금액 5,000원, 수수료 0.05%, 손절 5% 기준이다. 실제 값은 앱이 그때의 값으로 다시 계산한다.

## 3. 사용자 입력과 저장 검사

### 3.1 입력 항목

| 키 | 뜻 | 기본값 | 입력 규칙 |
|---|---|---|---|
| `buy.step_pcts` | 매수 단계별 비율(%) | `[100]`(한 번에) | 1~2개(D-083). 1% 단위 정수, 각 1 이상, 합 100 |
| `buy.next_step_drop_pct` | 2단계 하락률(%) | 2.0(D-086) | 매수가 2단계일 때만 쓴다. 0 < 하락률 < 손절%. 손절 %가 2% 이하이면 기본값을 비우고 직접 입력하게 한다(3.2 S7) |
| `sell.take_profit_steps` | 익절 단계: 발동 수익률(%)과 매도 비율(%) | 비어 있음(익절 꺼짐) | 0~2개(D-083). 발동 수익률은 0.5~500이고 단계마다 커야 한다. 매도 비율은 1% 단위 정수, 합 100 |

- 이전의 `buy.method`, `buy.split_count`, `risk.take_profit_pct`를 대신한다. 이전의 익절 하나(`risk.take_profit_pct` = x)는 익절 1단계(x%, 100%)와 같다.
- 익절 단계는 매수 단계와 함께 "단계 계획"이라 `sell.*`에 둔다. 위험 한도(`risk.*`)와 달리 진행 중인 포지션에는 바로 적용하지 않는다(4장 6번).
- 형식 예(값은 형식을 보이려고 넣은 임의의 값이고 권하는 값이 아니다):

```json
"buy": { "step_pcts": [50, 50], "next_step_drop_pct": "3.0" },
"sell": { "take_profit_steps": [ { "at_pct": "5.0", "sell_pct": 50 }, { "at_pct": "10.0", "sell_pct": 50 } ] }
```

- 화면: 마법사 W7과 설정의 매매 규칙 탭에 매수 단계 수(1·2), 단계별 비율, 균등하게 나누기 버튼(50/50), 하락률, 익절 단계 수(0·1·2), 발동 수익률과 매도 비율, 단계별 금액 미리보기(원), 필요한 코인별 예산을 보인다. 매수 2단계를 고르면 위험 안내 MSG-W013을 늘 보인다(5.2).

### 3.2 저장할 때 검사

마법사와 설정 화면에서 저장할 때 검사하고, 하나라도 못 맞추면 저장하지 않는다(MSG-E015, MSG-E020). 코인별 예산, 손절 %, 선택 코인 수, 일일 주문 수 상한, 최소 주문 간격, 시그널 평가 주기를 바꿀 때도 다시 검사한다.

| # | 검사 | 기준 | 못 맞추면 보여 줄 것 |
|---|---|---|---|
| S1 | 비율 합 | 매수 비율 합 = 100, 익절 매도 비율 합 = 100 | 지금 합 |
| S2 | 단계 수 상한 | 매수 ≤ 2단계, 익절 ≤ 2단계(D-083) | 상한 |
| S3 | 매수 단계 금액 | 모든 단계에서 단계 금액 ≥ F | 필요한 코인별 예산, 지금 예산으로 가능한 최대 단계 수 |
| S4 | 익절 단계(익절을 켰을 때) | 예산을 모두 샀다고 보고(원가 ≈ 예산 ÷ (1 + 매수 수수료)), 각 단계의 매도분 원가 ≥ 매도 최소 주문 금액이고, 마지막 단계 전까지 남는 원가 ≥ F | 필요한 코인별 예산 |
| S5 | 하루 주문 수(매수나 익절이 2단계일 때) | 선택 코인 수 × (매수 단계 수 + max(익절 단계 수, 1)) ≤ 일일 주문 수 상한 | 코인 하나에 쓸 수 있는 단계 합 = 내림(상한 ÷ 코인 수) |
| S6 | 주문 간격(매수가 2단계일 때) | 최소 주문 간격 < 시그널 평가 주기 | 두 값 |
| S7 | 하락률(매수가 2단계일 때) | 값이 있고, 0 < 하락률 < 손절% | 범위 |
| 경고 | 전체 노출 상한 | 선택 코인 수 × 코인별 예산 > 전체 노출 상한이면 저장은 하되 알린다. 나중에 사는 코인의 단계 금액이 줄거나, 첫 매수가 예산 하한에 못 미쳐 사지 않을 수 있다(D-067) | 필요한 전체 노출 상한 |

- S3은 첫 단계만이 아니라 모든 단계에 같은 하한을 쓴다. 첫 단계만 하한을 넘어도 손절 때 팔 수 있지만, 모든 단계에 같은 규칙을 써서 작은 주문을 막고 계산을 단순하게 한다.
- S5의 "max(익절 단계 수, 1)": 익절을 끄거나 1단계면 매도는 한 번(손절이나 그 밖의 전량 매도)이다. 익절 1단계를 판 뒤 손절하면 매도는 2번이다. 그래서 상한(매수 2·익절 2)에서 코인당 한 사이클 최대 주문은 4건, 코인 3개면 12건이다. 기본 상한 20건에서는 S5가 막지 않고, 상한을 코인 3개에서 11건 이하로 낮출 때 막힌다.
- S5와 S6은 나누지 않는 설정(매수 1단계, 익절 0~1단계)에서는 보지 않는다. 설정 범위를 바꾸지 않으려는 것이다.
- S5는 계획 한 사이클의 주문 수를 본다. 실행할 때는 실제 주문 수로 상한을 지킨다. 손절 매도는 상한 뒤에도 나가고, 사용자 명령 매도는 상한에서 뺀다(D-069). 상한 뒤 익절을 허용할지는 아직 정하지 않았다([요구사항 추적표](../08-quality/traceability.md) Q-02).
- S6: 2단계는 시그널 평가 때만 사므로 같은 코인의 두 매수 사이는 평가 주기(1시간 이상) 넘게 벌어진다. 최소 주문 간격이 평가 주기 이상이면 2단계가 계속 막힌다.
- S7: 손절 %를 낮추면 하락률도 함께 맞춰야 저장된다(예산 하한이 손절 %에 따라 바뀌는 것과 같은 방식).
- S7과 기본값 2%(D-086): 기본값은 손절 %가 2%보다 클 때만 S7을 지킨다. 손절 %가 2% 이하이면 다음처럼 한다. 저장 검사(S7) 자체는 바꾸지 않는다.
  - 매수 2단계를 고를 때 하락률 칸에 기본값을 채우지 않고 비워 둔다.
  - 하락률이 2%인 상태에서 손절 %를 2% 이하로 바꾸면 하락률 칸을 비운다.
  - 어느 경우든 MSG-W014로 알린다. 사용자가 손절 %보다 작은 값을 직접 입력해야 저장된다.
- 저장 뒤 기준값이 바뀌어(키를 넣은 뒤의 실제 최소 주문 금액 등) 검사를 못 맞추면 새 포지션의 첫 매수를 하지 않고(PLAN_INVALID) MSG-E015로 알린다. 진행 중인 포지션은 계획을 유지하되, 단계마다 승인할 때 위험 검사를 다시 한다.

### 3.3 못 맞출 때 보여 줄 값

- **필요한 코인별 예산** = 매수 필요 예산과 익절 필요 예산 가운데 큰 값.
  - 매수 필요 예산 = 올림(100 × F ÷ 가장 작은 매수 비율). 예: 50/50이면 11,580원, 60/40이면 14,475원, 70/30이면 19,300원.
  - 익절 필요 예산 = 올림((1 + 매수 수수료) × 다음 값들 가운데 가장 큰 값): 각 단계의 100 × 매도 최소 주문 금액 ÷ 그 단계 매도 비율, 마지막 단계 전 각 단계의 100 × F ÷ 그 단계 뒤 남는 비율. 예: 50/50이면 11,586원.
- **지금 예산으로 가능한 최대 매수 단계 수** = 1 또는 2. 50/50으로 나눌 때 S3을 지키면 2다. 예: 10,000원이면 1, 11,580원 이상이면 2.
- **하루 주문 수:** 코인 하나에 쓸 수 있는 단계 합 = 내림(일일 주문 수 상한 ÷ 선택 코인 수). 예: 20건, 코인 3개면 6.

## 4. 매수 단계 진행

1. **1단계**는 지금의 첫 매수와 같다(매수 조건 6개, 첫 매수 예산 하한 D-067).
2. **2단계:** 보유 중 시그널 평가(JOB-03)에서 매수 조건 6개([매매 로직 명세](trading-logic.md) 2장)를 다시 모두 만족하고, 평가 시점 현재가 ≤ 평균 단가 × (1 − 하락률/100)이면 산다(D-084). 아니면 STEP_DROP_NOT_MET로 기록한다. 현재가는 시세 웹소켓 ticker의 `trade_price`다(DEGRADED에서는 신규 매수를 하지 않는다).
3. **금액:** 단계 금액은 상한이다. 승인 금액은 지금 식(남은 코인 예산, 전체 노출, 주문 가능 원화, 수수료, [매매 로직 명세](trading-logic.md) 7장)으로 줄어들 수 있고, 매수 최소 주문 금액보다 작으면 사지 않는다(RISK_MIN_ORDER).
4. **체결 실패:** 단계 번호는 체결될 때만 올라간다. 2단계 최유리 FOK가 체결되지 않거나 거절되면 그 평가는 끝나고, 다음 평가에서 조건을 다시 본다(D-045 추천과 같은 방식).
5. **익절과의 관계:** 첫 익절 단계가 체결되면 그 포지션의 2단계는 하지 않는다(BUY_STEPS_DONE). 같은 포지션에서 사기와 팔기를 번갈아 하는 주문을 만들지 않는다([위험 관리 정책서](risk-policy.md) 7장). 2단계는 평균 단가보다 낮을 때, 익절은 높을 때라 보통 겹치지 않는다.
6. **계획 고정:** 포지션을 열 때(1단계 체결) 그때 설정의 매수 비율, 하락률, 익절 단계를 포지션에 저장하고, FLAT이 될 때까지 그 계획을 쓴다. 설정을 바꾸면 다음 포지션부터 적용하고 MSG-I010으로 알린다. 위험 한도(예산, 노출, 손절 %, 일일 손실, 주문 간격·수, 경고 종목)는 언제나 지금 설정으로 검사한다. 계획이 없는 포지션(재조정으로 수량을 맞춘 보유 등)은 매수 단계를 다 끝낸 것으로 보고, 익절 단계는 그 시점 설정으로 고정한다.
7. **평균 단가와 손절선:** 매수 단계가 체결될 때마다 평균 단가를 다시 계산하고(수량 가중, 수수료 제외), 손절선과 익절 발동 가격도 새 평균 단가로 바뀐다. 2단계는 평균 단가보다 낮은 가격에 사므로 평균 단가와 손절선이 내려간다(5.2). 매도는 평균 단가를 바꾸지 않는다.
8. **단계 진행 중 손절:** 2단계 주문이 끝나지 않은 동안 그 코인에 손절 주문을 낼 수 없고, 주문이 끝나는 즉시 새 평균 단가로 손절을 다시 점검한다(지금 규칙, D-070). 현재가가 새 손절선 아래면 방금 산 2단계까지 전량 판다.
9. **초기화:** FLAT이 되면 단계 번호, 익절 진행, 기준 수량, 계획을 지운다.

## 5. 2단계 조건(D-084)

### 5.1 정한 규칙

- 2단계는 "시그널 평가 때 매수 조건을 다시 모두 만족" + "현재가 ≤ 평균 단가 × (1 − 하락률/100)"일 때만 산다. 둘 중 하나라도 아니면 사지 않는다.
- 하락률은 사용자가 입력하고 저장할 때 0 < 하락률 < 손절%를 검사한다(S7). 하락률이 손절% 이상이면 2단계 조건보다 손절이 먼저 오므로 막는다. 기본값은 2%다(D-086, 9.6). 손절 %가 2% 이하이면 기본값을 쓰지 않고 직접 입력한다(3.2).
- 시그널 없이 가격만으로 2단계를 사지 않는다(1분 위험 점검에서 바로 사기 없음). 매수는 LLM 긍정 + 규칙 + 위험 한도라는 결정(D-006, D-114로 대체됨: 예상 결과 보고서 판정)과 평가 시점에만 판단한다는 제안(D-045, 대기·대체 후보)을 따른다.

### 5.2 운영 위험과 설정 화면 안내

- 손실 중인 포지션에 돈이 더 들어간다. 2단계를 사면 평균 단가와 손절선이 함께 내려가, 손절은 첫 매수 가격보다 더 낮은 가격에서 일어난다.
- 예(같은 금액 50/50, 하락률 2%, 손절 5%): 100원에 1단계, 98원에 2단계를 사면 평균 98.99원, 손절선 94.04원이다. 첫 매수가 기준으로 약 5.96% 떨어져야 손절된다. 한 번에 샀다면 95원(5%)이다. 하락률이 3%면 약 6.45%다.
- 손절선에서 판다고 보면 코인별 손실 금액은 "산 금액 전체 × 손절%" 근처로 묶인다(수수료·슬리피지 제외). 급락하면 체결가가 손절선보다 낮아 더 커질 수 있다.
- 2단계 조건을 만족하기 전에 가격이 손절선까지 내려가면(평가 사이에 급락) 2단계 없이 1단계만 손절된다.
- 화면 안내(MSG-W013): 매수 2단계를 고르면 위 위험과 지금 설정으로 계산한 값을 보인다. 첫 매수가 대비 손절 위치(%) = (1 − 100 × (1 − 손절%/100) ÷ (p1 + p2 ÷ (1 − 하락률/100))) × 100. p1, p2는 매수 비율이고, 하락률만큼 내려간 가격에서 2단계를 샀다고 본 값이다. 화면에는 소수 둘째 자리에서 반올림해 보인다.
- 예의 가격은 계산을 보이려는 값이고 앞으로의 가격이나 수익을 뜻하지 않는다.

### 5.3 결정 기록: 검토한 조건 후보

어느 후보든 매수 조건 6개는 시그널 평가 때 다시 맞아야 하는 조건이었다. 사용자는 B를 골랐다.

| 후보 | 2단계를 사는 때 | 노출 증가 | 손절선과의 관계 | 주문 빈도 | 결과 |
|---|---|---|---|---|---|
| A. 새 긍정 시그널만(이전 설계) | 매수 조건을 다시 모두 만족한 평가 | 가격과 상관없이 시그널이 다시 긍정일 때 는다 | 평균 단가가 새로 산 가격 쪽으로 움직이고 손절선도 따라간다 | 같은 코인 매수는 평가 주기(기본 4시간)에 한 번 이하 | 고르지 않음 |
| **B. + 하락** | 위 조건 + 현재가 ≤ 평균 단가 × (1 − 하락률) | 손실 중인 포지션에 돈이 더 들어간다 | 평균 단가와 손절선이 내려가 첫 매수가보다 더 떨어진 뒤에 손절한다(5.2). 하락률 < 손절%만 허용 | A와 같거나 적다 | **선택** |
| C. + 상승 | 위 조건 + 현재가 ≥ 평균 단가 × (1 + 상승률) | 이익 중인 포지션에 돈이 더 들어간다. 코인 예산이 평가액 기준이라 계획보다 덜 사거나 못 산다 | 평균 단가와 손절선이 올라가, 마지막 매수가에서 조금 내려도 포지션 전체가 손절될 수 있다 | A와 같거나 적다 | 고르지 않음 |
| D. + 시간 간격 | 위 조건 + 직전 단계 체결 뒤 T시간 이상 | 가격과 상관없이 시간에 따라 는다 | A와 같다 | 같은 코인 매수는 T시간에 한 번 이하 | 고르지 않음 |

## 6. 분할 매도(D-085)

### 6.1 적용 범위

| 매도 | 정한 방식 | 이유 |
|---|---|---|
| 익절 | 단계별로 나눔(최대 2단계) | 사용자 요청 |
| 손절 | 전량 | 손실을 줄이는 매도는 막지 않는다([위험 관리 정책서](risk-policy.md) 1장 원칙 2). 나눠 팔면 남는 부분의 손실이 손절%보다 커질 수 있다 |
| 정지 후 전량 매도, 모드 전환 매도, 선택 해제 매도 | 전량 | 사용자 명령. 지금 규칙(D-068, D-069) 그대로 |
| LLM 부정 매도 | 전량 | 청산 신호. 지금 규칙 그대로. 규칙상 청산은 D-105로 없다 |
| exit_only 실보유분(D-068) | 익절도 전량 | 실자산의 남은 관리를 단순하게 둔다 |

### 6.2 실행 규칙

1. 위험 점검(JOB-02, 60초)에서 평가수익률(평균 단가 기준)이 아직 팔지 않은 다음 익절 단계의 발동 수익률 이상이면 그 단계를 판다. 매도는 시장가다(7장).
2. 1단계 매도 수량 = 기준 수량 × 1단계 매도 비율 ÷ 100(거래소 수량 단위로 내림, 11장 확인 필요). 2단계는 남은 수량 전부를 판다.
3. 한 번 점검에서 두 단계의 발동 수익률을 모두 넘었으면 주문 하나로 전량 판다.
4. 다른 매도와 같은 위험 검사(끝나지 않은 주문, 최소 주문 간격, 일일 주문 수)를 받는다. 막히면 다음 점검에서 다시 보고, 그때 수익률이 발동 수익률 아래면 팔지 않는다.
5. 익절을 시작한 뒤에도 손절은 남은 수량 전체에 같은 손절선으로 걸린다. 평균 단가는 바뀌지 않는다.

### 6.3 남는 부분이 작을 때(잔량 규칙)

아래 가운데 하나라도 해당하면 그 단계에서 남은 수량을 전부 판다.

- 판 뒤 남는 수량을 손절선 가격으로 평가한 금액이 매도 최소 주문 금액 × 1.1보다 작다. 같은 뜻으로 "남는 수량 × 평균 단가 < F"다. 남는 부분이 손절선까지 내려가면 팔지 못할 수 있기 때문이다(예산 하한과 같은 기준).
- 그 단계의 매도분 평가액이 매도 최소 주문 금액보다 작다. 그만큼은 따로 팔 수 없다.

포지션 전체 평가액이 매도 최소 주문 금액보다 작으면 팔 수 없으므로 지금 잔량 규칙([매매 로직 명세](trading-logic.md) 10장)을 따른다. 이 규칙은 주로 매수가 계획보다 적게 된 포지션(2단계를 못 산 경우, 승인 금액이 줄어든 경우)에서 일어난다. 예산을 계획대로 다 산 포지션이면 S4를 통과한 계획에서는 보통 일어나지 않는다.

### 6.4 분할 손절(고르지 않음)

- 동작: 손절선에 닿으면 일부만 팔고, 나머지는 더 낮은 선에서 판다.
- 고르지 않은 이유: 남는 부분이 손절%보다 더 떨어진 뒤에 팔리므로 코인별 손실이 손절%를 넘을 수 있고, 손실을 줄이는 매도를 막지 않는다는 원칙 2와 맞지 않는다. 하락장에서 주문 수가 늘고, 남는 부분이 매도 최소 주문 금액 아래로 떨어져 팔지 못할 수 있다.

## 8. 예산 현실성

### 8.1 구성별 필요한 코인별 예산

기준: 매도 최소 주문 금액 5,000원, 손절 5%(F = 5,790원), 매수 수수료 0.05%, 코인 3개.

| 구성 | 필요한 코인별 예산 | 기본 예산 10,000원으로 | 코인 3개에 필요한 전체 노출 상한 | 손절 1번 손실 어림 | 3개 모두 손절 어림 | 기본 일일 손실 한도 3,000원 |
|---|---|---|---|---|---|---|
| 한 번에(기본) | 5,790원 | 가능 | 30,000원(기본 예산 기준, 기본값) | 약 500원(기본 예산 기준) | 약 1,500원 | 닿지 않음 |
| 매수 2단계 50/50 | 11,580원 | 불가 | 34,740원 | 약 579원 | 약 1,737원 | 닿지 않음 |
| 매수 2단계 60/40 | 14,475원 | 불가 | 43,425원 | 약 724원 | 약 2,171원 | 닿지 않음 |
| 매수 2단계 70/30 | 19,300원 | 불가 | 57,900원 | 약 965원 | 약 2,895원 | 닿지 않음 |
| 한 번에 + 익절 50/50 | 11,586원 | 불가 | 34,758원 | 약 579원 | 약 1,738원 | 닿지 않음 |
| 매수 2단계 50/50 + 익절 50/50 | 11,586원 | 불가 | 34,758원 | 약 579원 | 약 1,738원 | 닿지 않음 |
| (쓰지 않음, D-083) 매수 3단계 34/33/33 | 17,546원 | - | 52,638원 | 약 877원 | 약 2,632원 | 닿지 않음 |
| (쓰지 않음, D-083) 매수 4단계 25/25/25/25 | 23,160원 | - | 69,480원 | 약 1,158원 | 약 3,474원 | 넘음 |

- 손실 어림 = 코인별 예산 × 손절%. 손절선에서 체결된다고 본 값이고 수수료·슬리피지는 뺐다. 급락하면 체결가가 손절선보다 낮아 더 커질 수 있다. 수익이나 손실을 예측하는 값이 아니다.
- 3·4단계 행은 제안 때의 기록이다. D-083에서 매수 최대 2단계로 정해 쓰지 않는다.
- 기본 설정(코인별 10,000원)에서 가능한 것은 매수 1단계와 익절 1단계(전량)뿐이다. 매수 2단계(50/50)에는 11,580원, 익절 50/50에는 11,586원 이상이 필요하다.
- 비율이 고르지 않으면 작은 쪽 단계가 F 이상이어야 해서 예산이 더 든다(60/40은 14,475원, 70/30은 19,300원).
- 전체 노출 상한(기본 30,000원)은 코인별 예산을 올려도 저절로 바뀌지 않는다. 코인 3개 × 코인별 예산보다 작으면 나중에 사는 코인의 단계가 줄거나 첫 매수가 막힌다(3.2 경고).
- 일일 손실 한도는 그날 실현 손실이 닿으면 신규 매수만 막고 손절은 계속한다. 기본값 3,000원은 기본 예산 합(30,000원)의 10%로 잡은 값이라, 예산을 올리면 한도가 예산에 비해 작아진다.

### 8.2 단계 수와 하루 주문 수

기준: 일일 주문 수 상한 20건(기본). 한 사이클 최대 주문 = 매수 단계 수 + max(익절 단계 수, 1).

| 구성(매수 + 익절) | 한 사이클 최대 주문 | 코인 1개 | 코인 2개 | 코인 3개 |
|---|---|---|---|---|
| 1 + 0 또는 1 + 1(기본) | 2 | 2 | 4 | 6 |
| 2 + 0 또는 2 + 1 | 3 | 3 | 6 | 9 |
| 1 + 2 | 3 | 3 | 6 | 9 |
| 2 + 2(D-083 상한) | 4 | 4 | 8 | 12 |
| (쓰지 않음, D-083) 3 + 2, 4 + 2, 5 + 3 | 5, 6, 8 | - | - | 15, 18, 24 |

- 최유리 FOK가 체결되지 않아도 보낸 주문이라 주문 수에 센다([데이터 모델](../04-data/data-model.md) `daily_stats.orders_count`: 거절 포함). 상한 구성(2 + 2)에서도 코인 3개에서 8건이 남는다.
- 같은 날 FLAT이 된 뒤 다시 사면 사이클이 하나 더 생긴다. 실행할 때는 실제 주문 수로 상한을 지킨다.

## 9. 결정 기록

### 9.1 D-082 분할 구조: A 사용자 입력

| 선택지 | 내용 | 결과 |
|---|---|---|
| **A. 사용자 입력** | 매수 단계·비율과 익절 단계(발동 수익률·매도 비율)를 입력한다 | **선택**(2026-11-05) |

### 9.2 D-083 단계 수 상한: 매수 2·익절 2(사용자 값)

| 선택지 | 매수 최대 | 익절 최대 | 코인 3개 한 사이클 최대 주문 | 결과 |
|---|---|---|---|---|
| A(제안 때 추천) | 3 | 2 | 15건 | 고르지 않음 |
| B | 4 | 2 | 18건 | 고르지 않음 |
| C | 5 | 3 | 24건 | 고르지 않음 |
| **사용자 값** | **2** | **2** | **12건(8건 남음)** | **선택**(2026-11-05, 선택지에 없던 값을 직접 적음) |

### 9.3 D-084 2단계 조건: B + 평균 단가보다 하락

후보 비교는 5.3에 있다. 사용자는 B를 골랐다(2026-11-05). 하락률은 새 설정 항목 `buy.next_step_drop_pct`다.

### 9.4 D-085 분할 매도 범위: A 익절만 분할

| 선택지 | 내용 | 결과 |
|---|---|---|
| **A. 익절만 분할** | 6장. 손절과 그 밖의 청산은 전량. 남는 부분이 작으면 전량. 첫 익절 뒤 추가 매수 없음 | **선택**(2026-11-05) |
| B. 분할 매도 없음 | 익절도 전량 | 고르지 않음 |
| C. 익절과 손절 모두 분할 | 손절도 단계별로 나눈다(6.4) | 고르지 않음(제안하지 않은 선택지) |

### 9.5 D-043 주문 유형: A 제안 전체 승인

매수 최유리 FOK, 매도 시장가, 호가 기반 페이퍼 체결을 그대로 정했다(2026-11-05). 단계 주문에도 같은 유형을 쓴다(7장).

### 9.6 D-086 2단계 하락률 기본값: B 기본값 2%

2단계를 사려면 가격이 평균 단가보다 얼마나 내려가야 하는지(하락률)의 기본값을 정했다. 기본 매수는 1단계라, 하락률은 사용자가 매수 2단계를 고를 때만 쓴다.

| 선택지 | 내용 | 결과 |
|---|---|---|
| A. 기본값 없음(제안 때 추천) | 매수 2단계를 고르면 하락률 칸이 비어 있고, 입력해야 저장된다 | 고르지 않음 |
| **B. 예시 기본값을 둔다** | 값을 미리 채우고 "직접 정하세요. 투자 조언이 아닙니다"를 보인다 | **선택**(2026-11-06). 값은 2%(5장 계산 예시의 값) |

- 2%는 사용자가 직접 고른 값이며, 앱이나 지휘 세션이 권한 값이 아니다. 판단 자료로 [2단계 하락률 비교 리포트](../research/split-drop-rate.md)(외부 자료 조사 부록 포함)를 봤다.
- 저장 검사(0 < 하락률 < 손절%)는 그대로다. 손절 %가 2% 이하이면 기본값을 비우고 직접 입력하게 한다(3.2 S7, MSG-W014).
- 화면은 기본값을 채운 칸에도 "직접 정하세요. 투자 조언이 아닙니다"를 보인다(MSG-W013).
