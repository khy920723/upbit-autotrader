# 뉴스 수집 명세

상태: 쓰지 않음(약관, D-097, 2026-11-07) · 1~5장은 이전 설계 기록이다 · 관련: [ADR-0005](../06-architecture/adr/0005-news-sources.md), [LLM 시그널 명세](llm-signal.md), [법·약관 검토](../07-security-legal/legal-compliance.md), [4단계 시작 전 결정 묶음](../03-functional/stage4-decisions.md) 3장

## 0. 현재 결정 (2026-11-07)

- **뉴스를 수집하지 않는다.** LLM 입력은 시세·지표 요약만이다(D-097, [ADR-0005](../06-architecture/adr/0005-news-sources.md) 개정).
- **2026-11-10:** 시그널에 Claude 웹 검색을 쓴다(D-112). "LLM 입력은 시세·지표 요약만" 부분은 대체됐다. 앱이 뉴스를 직접 모으고 저장하지 않는 이 문서의 결정을 유지할지는 [분석 보고서 세션 제안서](../03-functional/analysis-report-session.md) S7(6.6절)로 묻는다. 검색 결과에 D-095·D-096 출처가 나올 때의 처리는 S5(6.5절)다.
- **이유:** 약관이 지금 설계(제목을 Gemini에 보내고 DB에 남김)를 허락하는 출처가 없었다.
  - 네이버 검색 API는 검색 결과의 AI 입력과 범위를 넘는 저장을 금지한다(D-095).
  - Cointelegraph는 AI·LLM 이용과 자동 스크래핑을 금지한다(D-096).
  - 스크래핑·구글 검색·Google 뉴스 RSS·Gemini 검색 그라운딩도 약관·robots.txt·무료 등급 조건 때문에 쓸 수 없다(D-095 근거).
  - CoinDesk는 사용자가 써도 된다고 판단했지만(C-1), 뉴스 없이 가기로 해 지금은 쓰지 않는다(D-097).
- **사용자 요구:** "일반적으로 제미나이나 코덱스 사용 시, 검색 시점을 기준으로 '특정 코인명'에 대한 긍정 시그널과 부정 시그널을 퍼센티지로 대략 유추해줘로 질문했을 때의 대답 정도만 있으면 됨. 뉴스까지 검색하지 않아도 됨."
- **4단계에서 만들지 않는 것:**
  - 뉴스 수집(`NewsSource`)과 FakeNews
  - `news_items`·`signal_news` 테이블
  - 네이버 키(마법사 W4, keyring)
  - `news.*` 설정과 MSG-E012
- **다시 넣을 때의 조건:**
  - 약관이 LLM 입력과 저장을 명시적으로 허락하는 출처, 또는 서면 허락을 받은 출처만 쓴다.
  - 공식 API나 RSS만 쓴다. 스크래핑과 robots.txt가 막는 수집은 하지 않는다.
  - 새 결정 번호로 결정 로그에 먼저 기록하고 ADR-0005와 이 문서를 고친다.
  - 아래 이전 설계(정리 규칙, 인젝션 방어, 저장)를 다시 검토한다.

아래 1~5장은 2026-11-03~11-07의 이전 설계다. 지금은 쓰지 않고, 다시 넣을 때 참고한다.

## 1. 원칙

- 공식 API와 RSS만 쓴다. 웹페이지를 긁어 오지 않는다.
- 제목, 링크, 출처, 발행 시각만 저장한다. 본문은 저장하지도 LLM에 보내지도 않는다.
- 화면에서 제목을 보여 줄 때 출처를 함께 표시한다.

## 3. 수집 방법

- **시점:** 시그널 평가 직전(4시간마다). 네이버 호출은 하루 18회 안팎이다.
- **네이버:** `query`는 코인 한글명, `sort=date`, `display=20`.
- **RSS:** 피드 전체를 받아 코인 영문명과 티커로 거른다(대소문자 무시, 단어 경계). 티커가 일반 단어와 겹치는 경우의 처리는 D-101에서 고르려 했으나 D-097로 필요 없어졌다(대체됨). 다시 넣을 때는 [4단계 시작 전 결정 묶음](../03-functional/stage4-decisions.md) 7장의 사실과 선택지를 다시 본다.
- **범위:** 최근 24시간, 코인당 최신순 최대 10개.
- **정리:** URL로 중복 제거, HTML 태그와 엔티티 제거, 제목 200자로 자르기.
  - 네이버 결과를 화면에 보이는 경우에는 이 정리가 네이버 검색 API 특약 2.2의 "가공 없이 노출"과 부딪친다. 네이버 제목에는 검색어와 맞는 부분에 `<b>` 태그가 들어 있고, 정리 단계가 이를 지우고 제목을 자르기 때문이다.
- **실패:** 실패한 출처는 건너뛰고 나머지로 계속한다(MSG-E012). 모든 출처가 실패해도 뉴스 없이 평가한다.

## 4. 저장

- news_items(제목, 링크, 출처, 시각)와 signal_news(어떤 시그널에 어떤 제목이 쓰였는지).

## 5. 확인한 것 (2026-11-07)

- 네이버 검색 API 이용약관(2026-10-07 개정)의 검색 API 특약 2.3은 데이터를 "AI에 입력하거나 학습, 개선, 평가 및 노출 등에 활용하는 행위"와 2.4 범위를 넘는 저장·캐싱을 금지한다. 2.4는 목적(기기는 장애 대응·개인화, 서버는 이력 조회)과 기간(기기 24시간 또는 새 질의까지, 서버 21일)을 함께 제한한다. 2.1·2.2는 네이버 검색결과 표시, 가공 없는 노출, 원본 링크를 요구한다. 개발자센터의 검색 API 신규 신청은 2026-07-30에 끝났다(부칙 제2조). 결과는 D-095(뺀다).
- Cointelegraph 이용약관 3절은 서면 동의 없이 콘텐츠를 AI·LLM의 학습이나 운영(operation)에 쓰는 것과 자동 스크래핑을 금지한다. 결과는 D-096(뺀다).
- CoinDesk 이용약관(2026-10-30 시행, 지휘 세션 확인): AI·RSS 조항은 없고 자동 수단 접근 금지(서면 허락 필요)와 개인·정보·비상업 목적 한정 조항이 있다. 이 세션은 자동 접근 검사 화면 때문에 원문을 읽지 못했다. 사용자 판단은 "본인 판단으로 쓴다"(C-1)이고, D-097로 지금은 쓰지 않는다.
- 보류 출처 RSS의 이용 조건은 확인하지 않았다.
