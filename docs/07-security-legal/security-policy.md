# 보안 정책·위협 모델

상태: 확정 · 관련: [리스크 관리 대장](risk-register.md), [로그·감사 기록 정의서](../04-data/logging-audit.md), [설치 가이드](../09-operations/install-guide.md)

## 1. 보호 대상

| 대상 | 위치 | 중요도 |
|---|---|---|
| 업비트 API 키(주문 권한) | Windows 자격 증명 관리자 | 최상 |
| Gemini 키, 네이버 키, 디스코드 웹후크 주소(`app-alarm`) | Windows 자격 증명 관리자 | 상 |
| 거래 기록(보유, 손익) | `%LOCALAPPDATA%\upbit-autotrader\data` | 중 |
| 매매 PC | 사용자 집 | 상 |

## 2. 위협과 대책

| 위협 | 영향 | 대책 |
|---|---|---|
| 매매 PC 악성코드가 키를 훔치거나 앱을 조작 | 원치 않는 주문 | 출금 권한 없는 키, 서브 포켓에 소액만, Defender 켜기, ESU 등록, 출처 모를 프로그램 설치 금지 |
| 자동 로그인 상태에서 누군가 PC를 만짐 | 앱으로 주문 가능, 계정이 관리자면 관리자 권한까지 | 로그인 직후 화면 잠금 작업 필수(설치 가이드), 장치 암호화(BitLocker 또는 장치 암호화), PC 물리 보안 |
| 자동 로그인 암호 노출 | Windows 계정 탈취 | Autologon은 암호를 LSA 비밀로 저장하며 관리자는 복호화할 수 있음을 인지. 지금 쓰는 계정을 그대로 자동 로그인하므로(D-033) 그 암호를 다른 서비스와 같이 쓰지 않음 |
| 키 유출(저장소, 로그, 프롬프트, 화면 공유) | 키 악용 | keyring에만 저장, 로그 가리기 필터, 프롬프트에 비밀 금지, 공개 저장소 규칙(CLAUDE.md), GitHub 비밀 검사, 화면에서 가림 |
| 유출된 키를 다른 곳에서 사용 | 원치 않는 주문 | 허용 IP 때문에 다른 위치에서는 동작하지 않음 |
| 뉴스 제목을 통한 프롬프트 인젝션 | 잘못된 매수 시도 | 데이터 블록 분리, enum 검증, 규칙 조건, 위험 한도 |
| 공급망(악성 패키지) | 코드 실행, 키 탈취 | `uv.lock`으로 해시 고정, 의존성 최소화, 올리기 전 변경 기록 확인 |
| 중간자 공격 | 키·주문 변조 | TLS 검증을 끄지 않음(업비트는 TLS 1.2 이상) |
| 디스코드 웹후크 주소 유출 | 그 채널에 가짜 알림이 올라옴 | 보내기 전용, 로그에서 주소를 가림, git-alarm과 다른 웹후크 |
| 지원이 끝난 OS | 알려진 취약점 | ESU 등록(2027-10-12까지), Defender 정의 업데이트(2028-10까지), Windows 11 이전 계획 |
| 가짜 exe 실행 | 악성 코드 실행 | 본인 저장소의 GitHub Actions 결과물만 사용, 커밋 해시 확인 |

## 3. 사고 대응

| 상황 | 조치 |
|---|---|
| 업비트 키 유출 의심 | 업비트 PC 웹에서 키 삭제 → 새 키 발급(권한 3개, 허용 IP) → 앱에 입력 → 거래 내역 확인 |
| Gemini·네이버 키 유출 | 각 콘솔에서 키 삭제·재발급 → 앱에 입력 |
| 디스코드 웹후크 주소 유출 | 디스코드에서 그 웹후크 삭제 → 새 웹후크 만들기 → 앱에 입력 |
| PC 감염 의심 | 앱 정지 → 업비트 키 삭제 → PC 점검·재설치 → 새 키 발급 |

## 4. 개발 중 보안 규칙

- 실제 키는 클라우드 세션, CI, 저장소에 두지 않는다. 테스트는 가짜 값만 쓴다.
- 저장소가 공개이므로 잔고, 주문 내역, IP, 계정 정보도 커밋하지 않는다.
- 이슈에 로그를 붙일 때는 가린 진단 묶음만 쓴다.
- 상세 규칙은 루트 `CLAUDE.md`의 절대 규칙을 따른다.
