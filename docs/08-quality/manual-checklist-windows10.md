# Windows 10 수동 점검표

상태: 초안(앱 화면이 생기면 메뉴 이름을 맞춤) · 2026-11-05 · 대상: 매매용 Windows 10 22H2 64비트 데스크톱 · 관련: [설치·초기 설정 가이드](../09-operations/install-guide.md), [운영 런북](../09-operations/runbook.md), [빌드·배포 절차](../09-operations/build-release.md), [추적표](traceability.md), [테스트 시나리오](test-scenarios.md) TS-45, TS-51~TS-53

자동 테스트로 확인할 수 없는 것을 사람이 Windows 10 PC에서 확인한다. 항목마다 절차와 기대 결과가 있다. 결과는 8장 양식으로 남긴다.

## 주의

- 결과를 저장소(진행 기록, 이슈, PR)에 남길 때 IP 주소, 잔고, 주문 내역, 계정 정보, 사용자 이름이 든 경로를 적지 않는다. 화면 캡처는 이 정보를 가린 뒤 쓴다.
- 이 점검에는 실제 주문이 필요 없다. 7절의 M-34만 live-validate(주문 검증 API, 실제 체결 없음)를 쓴다.
- 일부 항목(시계 변경, `powercfg /requests`)은 관리자 권한이 필요하다. 해당 항목에 적었다.
- PowerShell 명령은 시작 → "PowerShell" 검색 → 실행한다. 관리자 권한이 필요하면 마우스 오른쪽 클릭 → 관리자 권한으로 실행.

## 2. `--self-test`

| ID | 절차 | 기대 결과 |
|---|---|---|
| M-10 | PowerShell에서 `cd C:\Apps\upbit-autotrader` → `$p = Start-Process -FilePath .\autotrader.exe -ArgumentList '--self-test' -WorkingDirectory $PWD -Wait -PassThru; $p.ExitCode` | 창이 뜨지 않는다. `0`이 출력된다. 같은 폴더에 `self-test-report.txt`가 생기고 6개 항목(import, Qt, keyring, SQLite, TLS, 설정 경로)이 모두 통과이며 keyring 항목에 WinVaultKeyring이 나온다 |
| M-11 | 랜선을 뽑거나 Wi-Fi를 끈 상태에서 M-10을 다시 한다 | 결과가 같다(자가 점검이 네트워크를 쓰지 않음) |

- 앱은 창 모드 exe라서 `.\autotrader.exe --self-test`만 입력하면 PowerShell이 끝나기를 기다리지 않아 종료 코드를 볼 수 없다. 위처럼 `Start-Process -Wait -PassThru`를 쓴다. 설치 가이드 "자가 점검"의 명령에 `-PassThru`와 `$p.ExitCode`를 더한 것이다.
- 보고서는 UTF-8(BOM)이고 경로는 `%LOCALAPPDATA%`로 가려져 있어야 한다(D-065). 공유하기 전에 다른 개인 정보가 없는지 확인한다.

## 5. 재부팅과 잠자기 복귀

| ID | 절차 | 기대 결과 |
|---|---|---|
| M-21 | 앱을 RUNNING, PAUSED, STOPPED 상태로 각각 두고 재부팅한다(TS-43, TS-52) | 자동 로그인 → 앱 자동 실행 → 시작 점검 → 같은 상태로 재개 → 디스코드 MSG-I001. 재부팅부터 재개 알림까지 걸린 시간을 적는다 |
| M-22 | Windows 업데이트가 사용 시간 밖에 설치되고 재시작된 다음 날 확인한다(TS-53) | 09:00 일일 요약과 시작 알림이 왔고, 이벤트 로그에 재시작과 시작 점검 기록이 있다 |
| M-23 | 앱이 돌고 있을 때 전원 버튼을 길게 눌러 강제로 끈 뒤 다시 켠다 | 앱이 자동으로 다시 시작해 시작 점검을 통과하고 재개한다. DB 오류가 없다. (선택) 정전 뒤 PC가 저절로 켜지게 하는 BIOS 설정("AC 전원 복구 시 켜기" 등)이 있는지 적는다(RSK-02) |
| M-24 | 시작 → 전원 → 절전으로 PC를 재운 뒤 5분 뒤에 깨운다(TS-40) | 이벤트 로그에 잠자기 복귀, 웹소켓 재연결, 종목 갱신이 남는다. 실제 자산 포지션(live, exit_only)이 있으면 잔고·미체결 대조도 남는다(paper·live-validate 포지션은 대조하지 않는다). 잠든 동안 놓친 시그널 평가를 몰아서 하지 않는다 |
| M-25 | M-24 직후 로그에서 잠자기 복귀 줄을 찾아 "벽시계 경과"와 "monotonic 경과"를 비교한다 | 결과(잠든 동안 monotonic이 흘렀는지 멈췄는지)를 적는다(추적표 Q-13). 이 로그 줄은 7단계에서 만든다(구현 요청) |
| M-26 | 관리자 권한 PowerShell에서 `powercfg /requests`를 앱이 매매 중일 때와 STOPPED일 때 각각 실행한다 | 매매 중이면 SYSTEM 항목에 앱이 보인다. STOPPED일 때 결과를 적는다(추적표 Q-08) |
| M-27 | 설정 → 시간 및 언어에서 "자동으로 시간 설정"을 끈다. 관리자 권한 PowerShell에서 `Set-Date -Adjust (New-TimeSpan -Seconds 10)`으로 시계를 10초 앞으로 옮기고 앱을 다시 시작한다(TS-42) | 시작 점검 3번에서 DEGRADED와 MSG-E010이 나오고 손절 점검은 계속된다. "지금 동기화"를 누른 뒤 앱을 다시 시작하거나 다음 시계 오차 점검(JOB-09, 1시간)을 기다리면 원래 상태로 돌아온다. 걸린 시간을 적고, 끝나면 자동 시간 설정을 다시 켠다 |

- 설정 앱의 날짜·시간 변경 창은 시와 분만 바꿀 수 있어 초 단위로 옮길 수 없다. 그래서 M-27은 `Set-Date`를 쓴다. 앱이 실행 중일 때 바꾸면 시계 오차 점검(JOB-09)이 1시간마다라 바로 나타나지 않으므로 앱을 다시 시작해 시작 점검으로 확인한다.

## 7. 허용 IP 오류 대응

| ID | 절차 | 기대 결과 |
|---|---|---|
| M-32 | 공유기를 재부팅하기 전과 후에 "내 IP"를 검색해 공인 IP를 비교한다(설치 가이드 2장, D-018) | 바뀌었으면 유동 IP다. 같아도 유동일 수 있으므로(같은 IP를 다시 받는 경우가 있음) 통신사에 확인한다. 진행 기록에는 "고정·유동" 결과만 적고 IP 값은 적지 않는다 |
| M-33 | paper 모드, 업비트 키의 허용 IP는 집 IP인 상태에서 PC를 휴대폰 테더링에 연결해 공인 IP를 바꾸고 앱을 다시 시작한다 | 시작 점검 4번이 경고(paper는 HALTED가 되지 않음)이고 지금 공인 IP가 안내된다. paper에서 쓸 경고 문구는 결정 필요(추적표 Q-15. MSG-E001은 "자동 매매는 중지됩니다"라고 쓴다). 원래 네트워크로 돌아와 [다시 점검]을 누르면 통과한다 |
| M-34 | 9단계 live-validate를 시작할 때(주문은 검증 API로만 감) 같은 방법으로 공인 IP를 바꾼다 | 10분 안에 JOB-14가 감지해 HALTED, 디스코드 긴급 알림(NTF-03, MSG-E001, 지금 IP)이 온다. 운영 런북 2장대로 업비트 PC 웹 Open API 관리에서 IP를 추가하거나 원래 네트워크로 돌아온 뒤 [다시 점검] → 재개. 감지까지 걸린 시간과 복구까지 걸린 시간을 적는다 |
| M-35 | M-33·M-34의 알림과 화면을 공유하기 전에 확인한다 | IP가 가려져 있다(공개 저장소 규칙) |

## 8. 기록 양식

진행 기록에 아래처럼 요약해 남긴다.

```text
수동 점검 — 날짜: 2026-MM-DD, 앱 커밋: <해시 앞 7자리>, Windows 빌드: 19045.xxxx
통과: M-01~M-15, M-28~M-31
실패: M-24(웹소켓 재연결 기록 없음 → 이슈 등록)
해당 없음: M-34(9단계 전)
메모: PC 이름 ASCII, 유동 IP
```

- 실패한 항목은 이슈로 등록하고, 로그나 DB 원본 대신 금액·IP·주문 ID를 가린 진단 묶음만 첨부한다.
