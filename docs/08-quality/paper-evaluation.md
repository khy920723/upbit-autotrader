# 페이퍼 운영 평가 기준

상태: 확정 · 관련: [위험 관리 정책서](../03-functional/risk-policy.md) 6장, [ADR-0003](../06-architecture/adr/0003-paper-first-risk-precedence.md)

## 1. 목적

- 앱이 의도대로 동작하는지 확인하고 실적을 기록한다.
- 실전 전환은 사용자가 판단한다. 이 문서는 수익성 판단 기준이 아니며, 과거·페이퍼 실적은 미래 수익을 보장하지 않는다.

## 2. 기간 (인정일)

- paper 모드에서 RUNNING, PAUSED, BUY_BLOCKED 상태였던 시간의 합이 하루(09:00 KST 기준) 12시간 이상이면 인정일 1일이다.
- signal-only는 세지 않는다. 누적으로 세고, live에서 paper로 돌아와도 누적을 유지한다(초안).
- 인정일 28일이 지나야 실전 점검(live-validate)을 시작할 수 있다.
- LLM 시그널은 과거 데이터로 백테스트하지 않는다. 그래서 이 기간의 기록이 시그널을 판단하는 유일한 근거다.

## 3. 기록하는 지표

| 지표 | 정의 |
|---|---|
| 비용 반영 실현 손익 | 수수료·슬리피지를 뺀 손익. 코인별·전체 |
| 미실현 손익 | 평가 시점의 보유분 손익 |
| 최대 낙폭 | 누적 손익의 최고점 대비 가장 큰 하락 |
| 거래 수, 이익·손실 거래 수 | 매도 완료 기준 |
| 평균 보유 시간 | |
| 수수료 합계 | |
| 시그널 분포 | 긍정·부정·중립 비율, 실패율(status가 ok가 아닌 비율) |
| 차단 이유 분포 | RULE_NOT_MET, 위험 한도, MARKET_WARNING 등 |
| 손절 횟수 | |
| 가동률 | 인정 대상 상태 시간 / 전체 시간 |
| 알림 | 긴급·경고 건수 |
| 참고 비교 | 같은 기간 같은 코인을 단순 보유했을 때의 수익률(참고용) |

실전 전환 화면(SCR-08)과 일일 요약에서 이 지표를 보여 준다.

## 4. 실전 점검 전: 동작 점검과 체크리스트 A

동작 점검:

- [ ] 중복 주문 0건
- [ ] 위험 한도를 넘은 주문 0건
- [ ] 해결되지 않은 HALTED 없음
- [ ] 재부팅 후 자동 재개를 한 번 이상 확인
- [ ] 허용 IP 오류 대응 절차를 알고 있음
- [ ] 텔레그램 알림과 일일 요약을 매일 받음
- [ ] 가동률 90% 이상(초안)

체크리스트 A(SCR-08. 키 검증과 허용 IP는 앱이 확인하고, 서브포켓 키 여부와 권한 3개는 API로 확인할 수 없어 사용자가 확인 표시한다. D-048 대기):

- [ ] 업비트 키 검증 통과
- [ ] 입력한 키가 봇 전용 서브 포켓에서 발급한 키임
- [ ] 키 권한이 자산조회·주문조회·주문하기 3개뿐임
- [ ] 허용 IP가 현재 IP와 일치

## 5. 실전 점검 (live-validate)

- 주문을 업비트 주문 검증 API로 보내고, 통과하면 paper처럼 가상 체결로 포지션을 유지한다.
- 3일 이상(D-032). 앱이 3일 전에는 실전 전환 버튼을 열지 않는다.
- 기준: 매수 검증 오류(형식, 잔고, 마켓 상태) 0건. 실제 보유가 없어서 생기는 매도 검증의 잔고 부족은 예상된 결과로 따로 집계하고, 매도는 형식 오류 0건만 본다.

## 6. 실전 전환: 체크리스트 B

- [ ] live-validate 3일 이상, 매수 검증 오류 0건
- [ ] 코인별 예산, 손절, 일일 손실 한도를 다시 확인
- [ ] 알림이 실제로 오는지 확인
- [ ] 긴급 정지 버튼 위치와 동작을 알고 있음
- [ ] 봇 전용 서브 포켓에 감당할 수 있는 소액만 있음
- [ ] 확인 문구 "실전 전환" 입력

## 7. 주의

- 페이퍼 체결은 실제 체결(호가, 슬리피지, 부분 체결)과 다르다.
- 짧은 기간의 실적은 우연일 수 있다.
