# 요구사항 추적표

상태: 초안 · 2026-11-05 · 관련: [요구사항 정의서](../01-planning/requirements.md), [테스트 시나리오](test-scenarios.md), [불변식 명세](invariants.md), [가짜 구현 명세](fakes-spec.md), [로드맵](../10-management/roadmap.md)

요구사항(FR·NFR)이 어떤 설계 문서에 있고, 어떤 테스트 시나리오(TS)와 불변식(INV)으로 확인하며, 로드맵의 몇 단계에서 구현하는지 한 표로 본다. 테스트가 없는 요구사항과 요구사항이 없는 테스트를 찾아 "빠짐"으로 표시하고, 빈 곳은 [테스트 시나리오](test-scenarios.md)의 TS-98~TS-145로 메웠다.

## 1. 기준

- **요구사항:** main의 요구사항 정의서(FR-01~FR-26, NFR-01~NFR-12).
- **테스트 시나리오:** main의 TS-01~TS-97(TS-60~TS-97은 [1단계 설계](https://github.com/khy920723/upbit-autotrader/pull/2)와 그 후속에서 추가)과 이 추적표와 함께 추가한 TS-98~TS-145.
- **설계 문서:** 2026-11-05 main 기준(1단계 설계, 1단계 후속, 2단계 뼈대 병합 뒤). "대기"인 결정(D-xxx)에 기대는 내용은 결정 번호를 함께 적었다.
- **구현 단계:** [로드맵](../10-management/roadmap.md)의 단계 번호. 로드맵에 없는 것은 "단계 없음"으로 표시했다(Q-10).
- **판정**(TS-98~TS-145를 더하기 전 상태):
  - **충분:** 요구사항이 기대하는 동작을 시험하는 TS가 있다.
  - **일부:** TS가 있지만 요구사항의 일부가 빠졌다. 무엇이 빠졌는지 적었다.
  - **빠짐:** TS가 없다.

## 4. 요구사항이 없는 테스트

TS-01~TS-145를 2·3장 표와 대조했다. 아래 테스트는 요구사항 정의서의 어느 FR·NFR 문장에도 그 동작이 없고, CLAUDE.md나 설계 문서에만 근거가 있다. 일부는 가까운 요구사항 줄에 함께 적었지만 요구사항 문장이 그 동작을 요구하지는 않는다. 테스트를 지우는 대신 요구사항을 더하는 쪽을 제안한다(Q-11). 아래를 뺀 나머지 TS는 모두 2·3장 표의 어느 요구사항이 요구하는 동작을 시험한다.

| TS | 시험하는 것 | 근거 문서 | 판정 | 제안 |
|---|---|---|---|---|
| TS-15 | 보내는 헤더와 URL(Content-Type 1개, 슬래시 규칙) | CLAUDE.md, 업비트 API 연동 명세 6장 | 빠짐(요구사항 문장 없음) | NFR-13 외부 API 계약 준수 |

## 7. 갱신 규칙

- 요구사항, TS, INV를 더하거나 바꾸는 PR은 이 표를 함께 고친다([PR 검토 기준](review-checklist.md)).
- 구현 PR은 테스트 함수의 docstring 첫 줄에 시험하는 TS·INV ID를 적는다(예: `"""TS-01, INV-03: 타임아웃 뒤 조회로 확정"""`). QA는 `tests/`에서 ID를 찾아 이 표의 TS가 실제 테스트로 있는지 확인한다.
- 수동 시험(TS-45, TS-51~TS-53과 수동 점검표)은 결과를 [진행 기록](../10-management/progress.md)에 요약으로 남긴다. IP, 잔고 같은 개인 정보는 적지 않는다.
