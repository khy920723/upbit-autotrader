# 요구사항 (SPEC)

2026-11-03 사용자와 정한 내용이다. 요구사항이 바뀌면 이 문서부터 고친다.

## 1. 목적과 범위

- 업비트 원화(KRW) 마켓에서 최대 3개 코인을 자동 매매하는 개인용 Windows 데스크톱 앱.
- 실행 환경: Windows 10 64비트 22H2(빌드 19045) 이상.
- 하지 않는 것: 다른 사람의 자금 운용, 앱 판매나 시그널 제공, 고빈도 매매, 입금·출금 기능.
- 투자 자문이 아니다. 앱은 손실 상한을 지키는 데 집중하고, 성과는 페이퍼 실적으로 확인한다.

## 2. 사용자 요구사항

| # | 요구사항 | 구현 방향 |
|---|---|---|
| 1 | Windows 시작 시 자동으로 매매 시작 | HKCU Run 키(또는 시작 폴더)에 등록. 로그인 후 실행되고, 시작 점검을 통과하면 마지막 모드로 재개 |
| 2 | 키 같은 중요 정보는 최초 실행 때 입력받아 저장 | 첫 실행 마법사 → Windows 자격 증명 관리자(keyring) |
| 3 | 실행 시 전체 코인 목록 수신 | 실행 시와 이후 몇 시간마다 `/v1/market/all?is_details=true` 갱신 |
| 4 | 최대 3개 코인 선택, 긍정·부정 시그널로 매매 | 코인별 예산과 손절을 따로 관리 |
| 5 | 시그널은 무료 LLM으로 평가 | Gemini API 무료 등급. 무료 채팅 앱 자동화는 약관 위반 소지가 있어 쓰지 않음 |
| 6 | 손해는 최소, 이익은 최대 | 손실 상한을 코드로 강제. 수익은 보장할 수 없음 |

## 3. 실행 모드

| 모드 | 설명 |
|---|---|
| backtest | 과거 캔들로 규칙과 위험 관리만 검증. LLM 시그널은 쓰지 않음 |
| paper (기본) | 실시간 시세, 가상 체결. 수수료, 슬리피지, 최소 주문 금액 반영 |
| signal-only | 시그널과 "냈을 주문"만 기록 |
| live-validate | 주문을 `/v1/orders/test`로만 보내 검증. 실제 체결 없음 |
| live | 실제 주문. 사용자가 화면에서 확인 절차를 거쳐 켬 |

## 4. 시작 흐름

1. Windows 로그인 → 앱 자동 실행(중복 실행 방지).
2. 네트워크가 준비되면 시작 점검: 키 저장소, 업비트 키 유효성·허용 IP·만료일(실전 계열 모드), PC 시계와 거래소 시각 차이, 종목 목록과 경고, 잔고·미체결 주문 대조, Gemini 연결.
3. 하나라도 실패하면 매매하지 않고 화면과 텔레그램으로 알린다.
4. 통과하면 마지막 모드로 재개한다.

## 5. 첫 실행 마법사

- 업비트 Access/Secret Key와 발급일(만료 알림용)
- Gemini API 키와 모델 ID
- 네이버 검색 API Client ID/Secret
- 텔레그램 봇 토큰과 chat_id(선택, 테스트 전송 버튼)
- 코인 선택(최대 3개, 경고 종목은 표시하되 선택 불가)
- 코인별 예산, 손절 비율, 익절 비율(선택), 일일 손실 한도. 기본값은 낮게 둔다
- 모드(기본 paper), Windows 시작 시 실행 동의

## 6. 시그널

- 주기: 4시간(설정 가능). Gemini 무료 한도는 프로젝트 단위이고, 매일 태평양 시간 자정(KST 16~17시)에 초기화된다.
- 입력(코인별): 시세·지표 요약(추세, 변동성, 거래량)과 최근 뉴스 제목.
- 뉴스: 네이버 검색 API(news, sort=date, 한글 코인명으로 검색), CoinDesk·Cointelegraph RSS(코인명·티커로 거름). 제목과 링크만 쓰고 URL로 중복을 없앤다.
- 출력: `{signal: positive|negative|neutral, confidence: 0~1, reason}`.

## 7. 매매 규칙

- 매수: signal=positive, confidence ≥ 임계값, 규칙 조건 충족(1단계에서 정의, 예: 상승 추세), 위험 한도 통과, 경고 종목 아님. 모두 만족해야 한다.
- 매도: 손절, 규칙상 청산 조건, (선택) signal=negative이고 confidence ≥ 임계값.

## 8. 위험 관리 (항상 우선)

- 코인별 예산 상한과 전체 노출 상한
- 손절은 LLM 주기와 상관없이 1분마다 점검
- 일일 손실 한도에 닿으면 그날 신규 매수 중지
- 최소 주문 간격과 일일 주문 수 상한
- 유의·주의·거래지원 종료 예정 종목은 신규 매수 차단
- 418, 허용 IP 오류, 키 만료가 오면 매매 중지와 알림
- 긴급 정지: 신규 주문 중지, 선택에 따라 미체결 주문 취소와 전량 매도

## 9. 알림

- 텔레그램, 보내기 전용. 초당 1건 이하로 묶어서 보낸다.
- 체결, 오류, 손절, 매매 중지, 시작·종료, 일일 요약.

## 10. 기록과 운영

- SQLite: 주문(identifier, 상태 변화), 체결, 손익, 시그널(입출력 원문, 응답 모델명), 이벤트.
- 거래 기록 CSV 내보내기.
- 절전 방지(SetThreadExecutionState), 잠자기 복귀 감지 후 재동기화, 데이터 끊김 감시, 로그 회전, 키 만료 30일 전 알림.

## 11. 성과 확인과 실전 전환

1. paper로 몇 주 이상 운영한다(비용 반영).
2. 사용자가 판단해서 live-validate로 며칠 운영한다.
3. 업비트 서브 포켓에 소액만 넣고 live로 전환한다.
